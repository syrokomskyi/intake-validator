# `@warpgogol/intake-validator` — Agent Guide

RFC-1540: the published consumer validator for `werkstatt:intake/v2` hand-over bundles (INTAKE-01…34). werkstatt's `onboarding.intake.validate` calls it, and producers (pipelines) pin it as an exact devDependency and run its bin in their golden-conformance leg (`consumer.package`, RFC-1539, DNA-115).

**Workspace type:** Package (standalone, `forgePlugin: false`)

## Boundary rules

- This package MUST NOT import from `@warpgogol/werkstatt-engine` or `@warpgogol/werkstatt-site`. It depends only on `@warpgogol/werkstatt-shared`, `@warpgogol/pbp` and declared third-party packages. The engine depends on it, not the reverse.
- This package holds the only implementation of the INTAKE rules. Never copy a rule back into the engine or into a producer (DNA-115).
- `data/family-visitor-questions.generated.yaml` is GENERATED by `family.questions.export` (werkstatt-site) — never hand-edit it. `src/parity.test.ts` keeps it byte-equal to the site copy.
- `bin/intake-validate.mjs` registers the `tsx` loader because published `@warpgogol/*` packages ship TypeScript sources. Keep the bin a thin launcher; logic lives in `src/cli.ts`.
- A rule change that newly rejects bundles is a breaking change for producers. Flag it in its RFC.
